# BUY BUTTON · The Last Buyer

بازی وب داستانی پیکسلی با **انگلیسی پیش‌فرض** و هشت زبان: انگلیسی، فارسی، چینی ساده، عربی، اسپانیایی، هندی، فرانسوی و پرتغالی. نسخهٔ 0.6.0 شامل شهر آزاد، هشت فصل، ۲۴ پایان و رادیوی تعاملی است. زبان انتخاب‌شدهٔ بازیکن در ورودهای بعدی حفظ می‌شود.

## اجرا و ساخت

Node.js 24 و npm لازم‌اند:

```powershell
npm ci
npm run dev
```

نشانی توسعه: `http://localhost:4173`. فایل HTML را مستقیم با file:// باز نکنید. سرور محلی روی 127.0.0.1 گوش می‌دهد؛ برای انتخاب پورت از متغیر PORT استفاده کنید.

```powershell
npm run check
npm test
npm run build
npm run preview
```

پیش‌نمایش و توسعه به‌صورت پیش‌فرض از یک پورت استفاده می‌کنند؛ پیش از جابه‌جایی، سرور قبلی را متوقف کنید. موتور بازی وابستگی زمان اجرا ندارد. esbuild و playwright-core فقط ابزار توسعه‌اند.

## انتشار از GitHub به Vercel

راهنمای قدم‌به‌قدم اولین push و اتصال مخزن: [انتشار روی GitHub و Vercel](DEPLOY.fa.md).

فایل `vercel.json` در ریشهٔ پروژه قرار دارد:

| تنظیم | مقدار |
|---|---|
| Framework Preset | Other |
| Node.js | 24.x |
| Install | npm ci --include=dev |
| Build | npm run build |
| Output Directory | dist |
| متغیر محیطی و پایگاه داده | لازم نیست |

پوشهٔ همین پروژه را در مخزن GitHub قرار دهید و مخزن را از Vercel Import کنید. ریشهٔ پروژه باید همان پوشهٔ package.json باشد. تنظیم‌های نصب، build و output در vercel.json ثبت شده‌اند. ابزار ساخت نیز در نصب صریحاً لحاظ می‌شود. در این جلسه هیچ مخزن، commit، push یا استقرار ابری ساخته نشده است.

build کد را bundle و minify می‌کند و نام JavaScript، CSS، فونت و آیکون را با اثرانگشت محتوا می‌سازد. دارایی‌های نسخه‌دار کش بلندمدت دارند و HTML دوباره اعتبارسنجی می‌شود. فقط هفت فایل خروجی در dist قرار می‌گیرند؛ سورس، آزمون، تنظیم توسعه و نمونهٔ صوتی منتشر نمی‌شوند. خطای مسیر واقعاً 404 است. سیاست CSP با کد و سبک‌های بازی سازگار شده است.

گزارش حجم در `artifacts/build-report.json` تولید می‌شود. build با عبور از بودجهٔ ۳۵۰ KiB برای جمع gzip یا ۲۲۰ KiB برای JavaScript شکست می‌خورد. این اعداد برآورد فشرده‌سازی فایل‌ها هستند، نه زمان دانلود یا کارایی گوشی.

گردش‌کار `.github/workflows/ci.yml` روی push به main/master و pull request، نصب قفل‌شده، بررسی نحو، تست واحد و build را اجرا می‌کند. استقرار از اتصال مخزن به حساب Vercel انجام می‌شود.

مستندات پیکربندی: https://vercel.com/docs/project-configuration/vercel-json
و نسخهٔ Node: https://vercel.com/docs/functions/runtimes/node-js/node-js-versions

## تست دستگاه و کیفیت

پیش از نخستین سفر، آزمایش قابل‌مشاهدهٔ Canvas ارائه می‌شود: حدود ۲٫۲ ثانیه اجرای صحنهٔ پیکسلی با ۳۵۰ میلی‌ثانیه آماده‌سازی. میانه و صدک ۹۵ فاصلهٔ فریم‌ها، زمان ترسیم، تعداد نمونه‌ها و سهم فریم‌های کند نمایش داده می‌شوند. امتیاز از همین اندازه‌گیری‌ها به‌دست می‌آید؛ تعداد پردازندهٔ منطقی یا حافظه امتیاز را تغییر نمی‌دهد.

نتیجهٔ الگوریتم نسخهٔ ۲ با تاریخ، اندازهٔ پنجره و اطلاعات کلی گزارش‌شدهٔ مرورگر در `last-buyer.benchmark.v1` ذخیره می‌شود. این گزارش آزمون قطعی قدرت سخت‌افزار یا سنجش مستقل GPU نیست؛ ساعت نمایشگر و فشار فعلی مرورگر روی آن اثر دارند. اطلاعاتی که مرورگر ارائه نکند، خالی نمایش داده می‌شود. داده به سرور ارسال نمی‌شود.

نتیجهٔ معتبر در ورود بعدی دوباره مطالبه نمی‌شود. منوی Device check و تنظیمات امکان تکرار و دریافت JSON دارند. لغو، بسته‌شدن پنجره یا پنهان‌شدن صفحه آزمایش را قطع می‌کند. شکست ذخیره‌سازی به‌صراحت اعلام می‌شود؛ نتیجه برای همان جلسه کاربرد دارد. ادامه بدون آزمایش نیز ممکن است و امتیاز ساختگی تولید نمی‌کند.

نتیجه نقطهٔ شروع کیفیت خودکار است و انتخاب دستی بازیکن را عوض نمی‌کند. حالت خودکار در طول بازی فشار مداوم را می‌سنجد، پس از دو بازهٔ ضعیف سبک می‌شود و فقط پس از چهار بازهٔ پایدار کیفیت را بالا می‌برد. هدف نمایش ۶۰ یا ۳۰ فریم است؛ شبیه‌سازی در هر دو حالت گام ثابت ۶۰ هرتز دارد. پس‌زمینه‌ها پیش‌رندر می‌شوند و صفحهٔ پنهان متوقف می‌شود.

## گوشی و جهت نمایش

صفحهٔ لمسی کوچک با اندازهٔ پنجره و نوع اشاره‌گر تشخیص داده می‌شود؛ User-Agent لازم نیست. هنگام ورود به بازی، درخواست تمام‌صفحه و قفل landscape از همان تعامل بازیکن انجام می‌شود. در مرورگرِ پشتیبان، صحنه افقی می‌شود.

اگر مرورگر درخواست را نپذیرد، کارت راهنمای چرخاندن گوشی نشان داده می‌شود؛ صحنه و زمان بازی تا آماده‌شدن بازیکن متوقف‌اند. چرخش فیزیکی، چیدمان افقی را فعال می‌کند. گزینهٔ ادامهٔ عمودی برای دسترسی‌پذیری وجود دارد. با بازگشت به منو، قفل و تمام‌صفحه‌ای که خود بازی ایجاد کرده آزاد می‌شوند.

نمای افقی نوار ابزار کوتاه، دکمه‌های حداقل ۴۴ پیکسلی، حاشیهٔ امن بریدگی صفحه و بوم با نسبت درست دارد. مختصات لمس با قاب تصویر محاسبه می‌شوند؛ کل صفحه با CSS چرخانده نمی‌شود. تست مرورگر شامل ۸۴۴×۳۹۰ و ۵۶۸×۳۲۰، فارسی و انگلیسی، چرخش به عمودی و مسیر‌یابی واقعی با لمس است. این تست شبیه‌سازی است؛ گوشی فیزیکی و Safari هنوز بررسی نشده‌اند.

## بازی و کنترل

- میدان آزاد ۱۹۲۰×۱۲۸۰؛ هفت مسیر آزاد و بازار آخر که با کامل‌شدن مغازه، اتاق تسویه و دو فصل دلخواه باز می‌شود.
- هشت فصل، ۲۴ ایستگاه و ۴۸ مرحلهٔ معما، هشت صحنهٔ اختصاصی، ۳۲ سند و حداکثر ۱۵ تصمیم صریح.
- ۲۴ پایان در شش خانواده، هرکدام با سه قاب روایی؛ اطلس، سرنخ شرط‌های هر مسیر، حفظ سابقهٔ پایان‌ها و بازگشت به انتخاب آخر.
- شش کشف و سه پروژهٔ اختیاری: چراغ‌ها، نامه‌ها و ملودی گربه.
- سایه با دید محدود به دیوار، شنیدن دویدن، جست‌وجو و پناه. تعلیق تدریجی، پوشش پیکسلی، شدت قابل‌انتخاب و حالت آرام.
- راهنمای معما و حل کمکی؛ کمک، سرعت، ترس، زبان و دستگاه در گزارش بازتاب تصمیم‌ها امتیاز شخصیتی نمی‌سازند.
- WASD/جهت برای حرکت، Shift دویدن، E تعامل، Space نور رسید، C خم‌شدن، J دفترچه، M نقشه و Escape توقف. حرکت به مقصد با کلیک و لمس نیز وجود دارد.

گزارش پایان، انتخاب‌های همین سفر و شواهدشان را توضیح می‌دهد؛ تشخیص روان‌شناختی یا برچسب قطعی شخصیت نیست.

## موسیقی

نه قطعهٔ اصلی با چرخهٔ ۶۴ میزان، ملودی و تنظیم متفاوت، از سازهای Web Audio ساخته می‌شوند. رادیو شامل انتخاب قطعه، میکسر پنج لایه، کنترل جداگانهٔ موسیقی و محیط، سرعت ۶۰ تا ۱۳۲ BPM و چهار ردیف شانزده‌مرحله‌ای برای ساخت ریتم است. ریتم شخصی در تنظیمات ذخیره می‌شود و بازی تازه پاکش نمی‌کند.

حالت موسیقی همراه سفر، قطعه را با مکان هماهنگ می‌کند. موسیقی در صفحهٔ پنهان متوقف می‌شود. فایل صوتی تجاری یا دانلود حجیم صدا وجود ندارد. نمونهٔ شنیدنیِ ابزار آزمون فقط در `artifacts/tomorrow-radio-preview.wav` تولید می‌شود و در dist نیست. سنجش عددی صدا انجام شده؛ شنیدن انسانی و مسترینگ هنوز لازم است.

## ذخیره و تاریخچه

ذخیرهٔ بازی نسخهٔ ۴ است. نسخه‌های ۱ تا ۳ هنگام خواندن مهاجرت می‌کنند؛ سابقه‌ای که ثبت نشده جعل نمی‌شود. کلیدهای دیگر: `last-buyer.save.v1` و `last-buyer.settings.v1`. ذخیرهٔ خودکار، خروجی JSON و واردکردن فایل معتبر در دسترس‌اند. مراحل کامل‌شده حفظ می‌شوند؛ حرکات مرحلهٔ ناتمام پس از بستن همان مرحله از ابتدا آغاز می‌شوند.

اطلس پایان‌ها در سفر تازه حفظ می‌شود؛ هر پایان سابقهٔ تصمیم‌های همان سفر را دارد. بازگشت به انتخاب آخر، تصمیم‌های قبلی را تغییر نمی‌دهد. بعضی مسیرهای متناقض فقط در سفر تازه باز می‌شوند. پاک‌کردن دادهٔ سایت ذخیره‌ها را پاک می‌کند؛ پیش از آن خروجی بگیرید. هیچ کیف پول، خرید یا سفارش واقعی در بازی وجود ندارد.

## آزمون‌ها

برای آزمون مرورگر، Microsoft Edge نصب‌شده و `npm ci` لازم‌اند. ابتدا `npm run dev` را در ترمینال دیگر اجرا کنید:

```powershell
npm run test:browser
npm run test:mobile
npm run build
npm run test:release
```

آزمون انتشار سرور موقت خودش را از dist با هدرهای ثبت‌شدهٔ Vercel اجرا و در پایان می‌بندد. ابزارها از مرورگر جداگانه و دادهٔ ساختگی استفاده می‌کنند. مسیر داستان شخصیت را کنار اشیا قرار می‌دهد، سپس همهٔ معماها، صحنه‌ها و تصمیم‌ها از رابط واقعی اجرا می‌شوند. این روش زمان تجربهٔ انسان را اندازه نمی‌گیرد. نتایج و تصاویر در artifacts و گزارش خواندنی در [QA.md](QA.md) هستند.
